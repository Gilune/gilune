# Spike S4 — Offline Sync, Conflicts, and Relay

Status: **In progress** — convergence semantics green on Linux over a
shared-folder relay; encryption, causal frontiers beyond per-device
sequences, compaction, and device lifecycle remain.

Evidence prototype for ADR 0005 (operation-based sync) and the transport
shape of ADR 0008. As the spike plan requires, it **reuses the S2 data and
operation model** rather than inventing a parallel one: the harness lives in
`../s2-durable-capture` (`src/sync.rs`, `tests/s4_sync.rs`), where schema v2
made operations real — every durable change now records a self-describing
payload another replica can apply with no other context.

## The relay is a folder

```text
relay/
  ops/<device_id>/<seq, zero-padded>.json    # immutable, write-once
  blobs/<blob_id>/manifest.json + <i>.chunk  # 64 KB content chunks
```

Nothing else. Any dumb store that can replicate files — Dropbox, Syncthing,
a network drive, a USB stick — is a viable carrier, because every file is
written exactly once (tmp + fsync + rename) and never mutated. This doubles
as the first working evidence for ADR 0008's shared-folder transport and
for the operations-as-immutable-files layout question in
`08-open-questions.md`.

## Run it

```sh
cd ../s2-durable-capture && cargo test --test s4_sync
```

## Evidence so far (Linux, 2026-08-29; 10 scenarios, repeated runs clean)

- **Convergence** — two and three replicas with mixed writers reach
  identical state digests (objects, heads, revisions, tombstones), and the
  projected Markdown is byte-identical across devices.
- **Origin-device processing policy** — a replica that receives another
  device's capture stores it and waits; it creates no jobs and no
  processing runs. Pull-before-processing and pull-after both behave; only
  the originating device ever transcribes.
- **Concurrent edits preserve both heads** — the same transcript edited on
  two offline replicas (through their vaults, via the reconciler) syncs to
  two concurrent heads on both sides, and the projection surfaces
  `conflicted: true` instead of hiding a loser.
- **Idempotence and late joiners** — a second pull is a no-op; a fresh
  replica joining later converges from scratch.
- **Gap detection** — a missing sequence number halts that device's stream
  with a visible integrity alert; nothing past the gap applies until the
  file appears, then application resumes exactly where it stopped.
- **Adversarial input** — a corrupted operation file halts the stream
  safely with nothing half-applied; repairing it resumes cleanly.
- **Interrupted blob transfer** — an envelope applies before its bytes
  finish arriving; the vault projects a placeholder; the missing chunk's
  arrival completes assembly with a verified digest and byte-identical
  content.
- **Tombstones propagate** — an explicit deletion on one device clears the
  projection on the other while kernel history keeps the tombstone.
- **Unknown data** — an object of a type only one replica understands
  round-trips verbatim and projects generically elsewhere (constitution
  rule 9 across devices).
- **Migration under sync-era schema** — the v1→v2 migration that made
  operations syncable survives a mid-migration crash against a fixture
  generated by the real v1 binary, and a v1 database upgrades transparently
  on reopen.

## Honest gaps (not yet evidence)

- **No encryption**: operations and chunks are plaintext in the relay. The
  E2EE envelope, key hierarchy, and epoch/revocation model are untouched —
  deliberately, per the docs, pending the crypto ADR and external review.
- **Per-device sequences only**: no causal parents/frontier beyond them, so
  cross-device causality is not yet validated or enforced on apply.
- **No compaction or snapshot/bootstrap** for long-offline devices; the op
  log only grows.
- **No deterministic domain merge** (type-owner merge functions): conflict
  preservation only, which is the v0 default but not the whole contract.
- **No device enrollment/revocation**: device identity is just the stored
  ID; authentication is the filesystem.
- **In-process replicas**: convergence semantics are exercised across
  simulated restarts (every step reopens the kernel), but not across real
  processes or machines, and there are no crash-during-push/pull matrix
  runs yet (crash points exist; tests pending).
- **LAN transport**: the ADR 0008 first transport (discovery, pairing) is
  untouched; this spike proves the semantics and the shared-folder carrier.
